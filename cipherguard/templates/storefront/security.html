How we protect you

Six layers, each one useless on its own.

A password is a single point of failure. The account you create here runs through six independent checks, and every one of them writes to an audit trail that is hidden inside an image rather than a log file.

{{ artwork('safe') }}

The sign-in path

  1. 01
    Stretched password hashes Nothing is stored in the clear. Each password is salted and run through PBKDF2-SHA256 so a stolen file is expensive rather than instant.
  2. 02
    Honeywords Alongside the real hash sit nineteen decoys. Cracking the file gives an attacker twenty candidates with no way to rank them, and using a decoy raises an alarm instead of opening the account.
  3. 03
    Keystroke rhythm Hold times and gaps between keys are captured at enrolment. A sign-in that types nothing like the profile is still allowed through, but it is scored as risky and recorded as such.
  4. 04
    Time-based codes Optional but recommended: RFC 6238 codes from any authenticator app, verified with a one-step window either side to allow for clock drift.
  5. 05
    Lockout Five consecutive failures freeze the account for five minutes. Credential stuffing gets nowhere, and the response is identical whether or not the username exists.
  6. 06
    Encrypted recovery The answer to your recovery question is enciphered with a Vigenère or Playfair key derived from a per-account salt, so the stored value is never the answer itself.

Where the records live

Two carriers, both images, both tamper-evident.

Audit trail

Sign-ins, decoy hits, lockouts, injection probes and checkouts are appended to the least significant bits of a carrier image. Edit the image and the payload stops parsing.

Sealed invoices

Each order is serialised, encrypted with a keystream and stamped with an HMAC before it is embedded. The order page reports whether the seal still verifies.

Injection honeypot

Search terms that look like SQL are compiled into a query that is displayed and then discarded, while the attempt is written to the audit trail.

Request log

Method, path, status, address and user agent for every request, kept as plain JSON because volume matters more than secrecy there.
